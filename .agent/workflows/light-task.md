# 소규모 작업 (Light 레인)

버튼 색 하나 고치는 데 SPEC + 계약 + QA 는 과하다. 이 워크플로는 그런 작업용이다.

**Heavy 레인으로 올려야 하는 신호** — 다음 중 하나라도 해당하면 중단하고, 사람에게 `/harness` 로 계약을 먼저 받으라고 알린다.

- 3개 이상의 파일에 걸친 구조 변경
- 데이터 모델·Repository 인터페이스 변경
- 새 라우트/새 화면 추가
- 두 앱 모두에 영향을 주는 공유 패키지 변경

## 1. 컨텍스트 로드

1. 루트 `AGENTS.md`
2. `.agent/rules/` 전체
3. UI 작업이면 `docs/ui-conventions.md`, 화면 로직이면 `docs/ui-logic.md`

지시문에 **검증 기준이 없으면 먼저 만든다.** "무엇을 클릭하면 무엇이 보여야 하는가" 형태로 2~3줄. 사람에게 확인받고 진행한다.

## 2. 브랜치

```bash
git status && git branch --show-current
```

- `main` 이면 `fix/<짧은-슬러그>` 또는 `feat/<짧은-슬러그>` 브랜치를 만든다.
- 이미 작업 브랜치이고 다른 도구의 미커밋 변경이 있으면 덮어쓰지 말고 사람에게 알린다.

## 3. 구현 → 검증

- 지시받은 범위만 고친다. 눈에 띄는 다른 문제는 고치지 말고 보고에 적는다.
- 정적 검증:
  ```bash
  pnpm build
  pnpm --filter momozzang-invitation lint    # 건드린 앱만
  ```
- **브라우저 확인은 생략하지 않는다.** dev 서버를 띄우고 모바일 뷰포트(375×812)에서 1단계의 검증 기준을 직접 수행한다.
- 시각 변경이 있으면 before/after 스크린샷을 남긴다(저장소에 커밋하지 않아도 되며, 보고에 첨부).

## 4. 커밋 + 보고

- `.agent/rules/20-git.md` 의 한글 `feat:`/`fix:` 컨벤션으로 원자적 커밋. push 는 하지 않는다.
- 보고 형식:

```
변경: <한 줄>
검증: <브라우저에서 실제로 한 조작> → 통과/실패
커밋: <해시> <메시지>
남긴 문제: <범위 밖이라 손대지 않은 것, 없으면 "없음">
다음: Claude Code 창에서 /pr
```
